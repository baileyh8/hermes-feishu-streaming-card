# V4.7.3：心跳缺失时的扫描降频与健康接口修复

- **#378 / PR #379**：完整源码检测确认安装有效、且仅等待心跳时，后续完整复查间隔改为检测结束后 300 秒。监视循环仍检查最新 readiness；恢复或进入其他保护状态会清除这一观察结果。缓存不用于授权修复。
- **健康接口**：`/health` 和状态查询读取最后一次完成的诊断快照，不再等待后台扫描/修复锁。诊断计数可能落后于当前扫描，readiness 仍独立读取。
- **#372 恢复说明**：明确重新绑定同时更新 `target_identity` 和 `plan_fingerprint`；中间出现 `gateway_restart_required` 需重启 Gateway，不能误认为恢复失败。服务管理器的 KeepAlive 不应在确认前重新拉起 sidecar。
- **测试稳定性**：审批过期测试先确认回调进入，再推进测试时钟；不改变实际审批期限或授权规则。

## 升级

使用原安装入口升级 HFC，重新运行官方 setup/install，再通过原服务 owner 重启 sidecar 和 Gateway。Hermes 本体无需因本补丁升级。保留现有配置、状态文件和安装 manifest。

## 验证与限制

已覆盖重复扫描、复查到期后重新检测、心跳恢复、保护状态、失败路径，以及后台检测被阻塞时的真实回环 HTTP 请求。发布 CI、精确合并和安装包核验结果见 Release 最终记录。

单次源码扫描的 CPU 成本未改变；变化后的源码在下一次完整复查时发现，存在约五分钟加轮询与扫描耗时的延迟。未将报告者 WSL 的 CPU 和延迟数值写成已在本机复现。无卡片布局改动，也不声称新增移动端视觉验收。
