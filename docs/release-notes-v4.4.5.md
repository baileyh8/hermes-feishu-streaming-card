# V4.4.5 — 终态与安装稳定性修复

## 修复

- Hermes 明确返回失败、中断、partial 或 completed=false 时，卡片保留已有结果并显示未成功终态，不再发送“任务已完成”通知。覆盖 #285 与 #274 的显示问题；不声称修复上游停止执行的根因。
- 新消息替代仍运行的旧轮时，旧卡保留部分正文并提示“本轮已被新对话替代，任务尚未确认完成”。晚到事件不会翻转旧卡或污染新轮。
- 支持 #281 / PR #286 提供的 Hermes decomposed `send_final_ledgered` 契约。保留严格、幂等和可逆的安装边界，并拒绝参数、adapter、终态 guard 和投递控制流漂移。感谢 tidytorch 的兼容性贡献。

## 验证与维护

增加补丁实际执行顺序、成功/失败投递、缺失账本 ID 和危险源码漂移回归。稳定性测试规则写入维护指南、AGENTS 与 PR 模板，要求记录真实客户端证据和未运行项目。

实现候选全量测试：3562 passed、9 skipped。跳过项涉及 Windows、PowerShell、独立 SDK 环境和未配置的上游固定源码目录；发布仍由精确提交上的跨平台 CI 把关。

## 边界

#282 授权首次点击、#283 长时间空卡、#275/#278 Topic 路由仍待定位。#284 反复 fence 不能通过手动清除安全标记解决；本版没有放松完整性验证。兼容性依据已验证源码契约，不能据此保证所有标为 Hermes 0.21.1 的分发版本。
