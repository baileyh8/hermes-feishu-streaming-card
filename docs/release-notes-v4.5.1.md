# v4.5.1：CardKit 与话题、审批稳定性修复

本版整合 [mouyong](https://github.com/mouyong) 的 PR #310，并补充维护者审查修复。

- #316/#317：兼容 Hermes `6005aa1fd9` 抽取后的 clarify helper；保留二元返回契约，拒绝参数、上下文、调用返回形状及 async 漂移。新增固定源码 SHA 的安装、重复安装、诊断及卸载还原 CI。

- #306：真实飞书接口可复现长时间线 ID 引发 300301。CardKit 边界统一为不超过 20 字符的稳定唯一 ID，创建、增量和终局更新使用一致映射；失败日志只记录实体哈希、请求哈希、大小、序号和错误码，不记录正文和原始标识符。
- #305/#313：后台任务保留原始消息锚点；附件、通知缺少锚点时从指定话题解析。
- #307/#312：失败时保留已输出内容，审批后保留原问题、操作范围和选择结果。
- #314：暂停审批复用原卡，等待期间维持活动心跳。只有原任务仍在等待的可暂停审批才允许重新审批；失效任务明确要求重新发送原请求，不伪造新任务。
- #282：审批顶部区分手机“展开”和实际授权，完整操作范围保留在授权按钮之前。Android/iOS 原报告场景尚未真机验收，Issue 保持开放。
- #311：重启拒收提示与普通心跳分离，显示请求未开始、完成后需重发；真实重启完成事件显示明确结果，不推测完成时间。
- #304：标题显示执行状态、耗时和工具次数，展开区域增加明确提示。

维护者审查额外修正：心跳自动撤回只作用于独立心跳通知，不能撤回会话正文或终局答案。

验证：回归测试和真实 CardKit 未发送实体测试；未向聊天发送测试消息。移动端展示与报告者后台任务、重启全过程仍需现场复测，不以自动化通过替代真机验收。

2026-09-17 报告者已在 #305、#307、#311、#312、#313、#314 明确确认 PR #310 实测通过；#290 确认为用户技能相关。以上是贡献者现场证据，与维护者自动化及未发送实体测试分别记录。#282 最新线索为小屏幕展开与授权按钮重叠，仍未确认最终修复。
