#328/#333 的原开关已在 4.6.2/4.6.3 交付，本轮增加可选组合和解释工具。已有终局恢复、失败保文、话题路由和展示检查点是不可回归的底线，不重新包装为新功能。PR #331 按子项吸收，不整包合并；归因见[发布候选说明](../../release-notes-v4.6.4.md)。

## 完成顺序与门禁

1. **候选实现及模块回归**：保留首次按钮、续答、作用域通知与旧 owner 方言的失败复现；运行相关 focused、实际生成 hook、SDK 和 HTTP/检查点回归。独立审阅发现的缺口必须补实执行用例。
2. **集成候选验证**：完整 pytest、diff 检查；固定 Hermes 安装/重复安装/还原；普通 wheel 来源和配置兼容；中断、终局恢复、容量保护与多 profile/topic 的组合验证。
3. **真实实例验收**：复用授权实例/会话，核对实际配置、包路径、版本、服务和身份；验证桌面首次点击与顺序阅读，手机/故障注入未运行的项目单独标注，不能由 mock 或旧版本实测替代。
4. **发布门禁**：精确合并 SHA 的 CI、annotated tag、三平台资产/checksum、公开 tag 普通安装；分别记录生产升级和真实客户端证据。发布与关闭 issue 以证据为准，不以时间窗口、测试数量或相邻修复替代。

4.6.4 的发布已完成；真实实例和客户端步骤的当次结果由[本轮验收清单](../../wiki/feishu-acceptance-v4.6.4.md)与发布交付记录确认，本文不预先勾选。

## 关键验收

- 冷启动第一题/第一条审批，不用 slash/model/resume 预热；一次点击只唤醒一次原等待方，生成闭包没有 self/runner 也能正确路由。
- 单选、多选、自定义答案、连续两题、拒绝、过期/重审；旧题 token 和旧审批不得作用于新题，编辑中不被无关 PATCH 清空。
- 选择前后的正文、问题、操作范围、工具、附件和整轮统计可回看；新段在选择之后，直接下一题无空卡。
- 新续答 create 失败/不确定、重复/晚到事件、旧 animation、终局与重启；只有确认新 owner 后切换。唯一 legacy owner 始终同方言，展示恢复不恢复执行。
- 精确 bot/profile/chat/topic、空 thread 与首回复建 thread；通知无法证明同一作用域时保留。失败删除、容量、迟到删除不得误撤回答案和回执。
- 缺省和旧 YAML 无变化；focused/detailed 与多层显式覆盖、completed/failed、长思考/表格/代码及回退一致。card-config 解释不是已重载证明。
- preflight 错误 cwd/解释器、缺 fixture、真实 pytest 非零和提交差异空白错误都如实报告，不接触生产 operations target。

真实验收清单需分别记录桌面与实际可用手机设备。无法验证的 #282 等历史现场问题继续保留边界；#335 的当前客户端行为要独立复验，不能仅凭贡献者此前实测或本轮自动化关闭。

## 本轮不扩大的范围

不自动改变阅读默认，不实施全量架构重写、第二套执行/授权队列、跨会话任务看板、全功能设置 UI 或长答案文件导出。AMD/9Router 运维、默认模型切换与 Hermes 核心升级属于独立任务。Obsidian 镜像由主任务按授权处理；本文不包含私有运行目标。
