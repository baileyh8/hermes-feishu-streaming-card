# 思考与审批卡片的阅读方式

`card.reasoning_format` 支持 `panel` 与 `code`，默认 `panel` 保留原来的折叠时间线。
需要直接阅读思考片段时可以配置：

```yaml
card:
  reasoning_format: code
  max_reasoning_chars: 1200
  timeline_expanded: false
```

`code` 把已记录的思考片段作为 fenced text block 放在卡片正文，工具记录仍保留在可折叠面板。
同一项可以配置在 profile 或 bot 的 `card` 映射中。`show_reasoning: false` 继续隐藏思考与工具时间线，
`max_reasoning_chars` 与 `max_timeline_items` 继续限制每次展示内容；卡片仍经过统一大小检查。

审批卡片展示完整命令和操作说明。命令使用经过转义的普通 Markdown，避免 fenced code 长行必须横向滚动，
并防止命令中的链接、标签和格式符号隐藏授权范围。文本交互模式的审批卡省略此前的回答和工具历史，
让完整授权范围与选择靠在一起；按钮回调模式原本就使用独立审批布局。

审批内容不再在第 3,000 个字符处静默截断。若转义后审批正文的 JSON 编码超过 12,000 UTF-8 字节，
hook 不发送交互卡并交还 Hermes 原生审批流程，给卡片头部、按钮和回调字段保留容量。
返回原生流程不是批准；不生成针对不完整命令的授权按钮。

审批和澄清的单选按钮使用 `1`、`2`、`3` 等短编号；正文同时列出编号与完整选项说明，
不会把长说明挤进按钮。原始选项值、callback token 与权限校验不变。
除 hook 的正文预检外，sidecar 还对带完整选项的最终交互卡检查大小；无法完整显示时
在接管之前返回原生流程，不发送可点击的截断审批。

未声明暂停能力的旧审批路径，过期或失败后仍按拒绝处理，不在主话题流重新发起原生审批。支持暂停的 Gateway 路径见下文。
sidecar 在原卡上显示过期状态；晚到点击不会重新生效。超时尚未确定是否成功接管的
网络错误继续遵循原有单次请求与只读状态查询，不重放审批请求。

## 交互记录

交互完成后，卡片正文保留原问题、完整选项和选择结果；过期/失败也保留原问题与选项，
并移除可执行控件和 callback 凭据。回看不依赖鼠标悬停，手机可以直接阅读。
仅展示问题、选项和结果，不把审批命令详情复制到完成态。

## @ 提及

普通 `@昵称` 是正文文本，不等于飞书可通知的用户提及。正文已有合法 open ID 的
`<at id=ou_example>显示名</at>` 会保留，但 HFC 不从昵称猜测或搜索收件人。
交互提醒可以使用已验证的本轮发送者身份。模型输出仅包含昵称时，需要上游提供
正确的身份映射；渲染器不能安全补出该 ID。自动测试验证标签保真，不代表已验证
飞书客户端产生了通知。

自动测试覆盖内容尾部保留、Markdown 转义、超限回退、配置继承以及思考代码块与卡片大小限制。
手机和桌面端的实际换行、滚动行为仍需真实 Feishu/Lark 客户端复测。

## 手机长问题与提及位置

超过 40 个字符的交互问题会在正文中完整显示，避免手机标题截断后无法阅读。
完整选项仍位于短编号按钮之前，审批命令保留原有转义和完整性检查。

正文中的 `@姓名` 只在姓名与入站消息提供的当前提问者身份一致时转换为真实 `<at>`。
未知用户、代码块、行内代码和链接保持原文；不根据模型输出猜测其他用户的 open_id。
`card.mentions_in_cards: false` 同样关闭这项转换。

完成提醒可选择放在答案卡片正文前：

```yaml
card:
  completion_notify:
    enabled: true
    placement: card
```

默认 `placement: message` 保留原来的独立消息提醒。`card` 只改变卡片中的展示位置，
卡片编辑不保证触发客户端推送；需要新消息通知时使用 `message`。完成通知文字为
“本轮回复结束”，表示本轮模型响应已经结束，不代表业务目标已经通过验收。

## 过期审批暂停

当前 Gateway 的可取消同步审批回调会声明 `pause_on_timeout` 能力。此路径到期后，
sidecar 撤销旧审批 token，发布“任务已暂停，等待审批”卡片；Gateway 保持原工具调用阻塞，
不把超时转换为用户拒绝，也不让模型继续寻找替代执行路径。

“查看并继续审批”仅恢复审阅窗口，不代表同意操作。它要求原 Gateway 仍在轮询，
并再次更换 token；用户必须在新的完整操作说明和按钮上明确选择。过期按钮、旧恢复按钮
与不再等待的执行都不能获得授权。支持 request_id 的 Hermes 按原审批队列项解析结果，
不会把迟到同意应用到另一条排队命令。

这项能力针对仍存活的同步 Gateway 审批回调。它不序列化执行栈，不恢复重启前的工具调用，
也不延长 native runtime admission 的过期证明；未声明该能力的旧运行时保持原有过期行为。
