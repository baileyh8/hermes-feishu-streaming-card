# V4.6.5 验收记录

本版承接 [4.6.4 的生产与真实客户端记录](feishu-acceptance-v4.6.4.md)。截至候选验证，本机运行公开 4.6.4，Gateway/sidecar ready，版本及普通 site-packages 来源已确认。一次真实 clarify 请求因 DeepSeek 三次 HTTP 503 终止，工具调用为 0；它证明失败卡与重复灰色提示的现场现象，不证明首次按钮可用。

后续桌面补测已观察真实 A 选择与回执下方续答，详见 4.6.4 记录；同时复现旧卡仍显示执行中。本候选加入保留历史的中性旧段收尾，4.6.5 升级后的结果独立验收。

## 自动化与发版

- 续答成功才收尾旧卡；失败创建不收尾、旧 PATCH 失败不阻断、唯一 legacy 方言与回执保持，原回合状态及历史不变。
- 生成状态 callback 实际执行；已知错误的明确 HTTP ACK 才抑制原生提示，缺字段/拒绝保留，同 loop 不阻塞。
- 持久通知两次重启、冷却/代次、错应用与跨话题、损坏文件及写失败；来源 wrapper 与普通引用隔离。
- 明确 call_id 的重复终态和迟到 start、持续时间/计数与历史；可选正序及分组显示保留默认。
- 固定上游源码安装、严格旧 hook 迁移、重复安装、Git index/本地定制保留及卸载还原。
- 最终完整回归、CI、精确合并、annotated tag、资产/checksum 与公开 tag 普通安装结果随 Release 登记；候选测试不能替代这些门禁。

## 尚需真实客户端证据

首次 clarify/approval 按钮、点击后顺序续答、原生通知在同话题新回复后消失、模型故障不再重复灰色提示，以及桌面/手机可读性。复用已授权应用/测试会话，不用 slash/model/resume 预热来冒充冷启动。模型仍不可用时保留阻塞，不擅自切默认模型；未复验问题不关闭。
