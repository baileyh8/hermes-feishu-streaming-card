# V4.6.5 — Notice lifecycle and failure feedback

This patch continues the V4.6.x experience plan without changing reading defaults. AMD/9Router operations, default-model changes and Hermes core upgrades remain separate.

- Retire the previous schema-2 card only after confirmed continuation. Preserve the pre-output snapshot and decision receipt, use neutral handoff text instead of turn success, skip legacy owners and keep the new owner if the old PATCH fails. Adapted from PR #339; unconditional removal of decided approvals remains separate. Text-mode receipts become static after a decision, including consecutive questions and interaction-first owners.
- Persist exact profile/bot/chat/thread restart-notice ownership across sidecar restarts. Recognize only known native startup/home/shutdown producers with matching adapter and application identity. Ordinary answers quoting the same text remain untouched; failed deletions retain retry ownership.
- Deduplicate explicit executor `call_id` / `tool_call_id` terminal events, preserving counts, ordinals and duration; late starts cannot reopen completed calls. Legacy name-only events retain their existing behavior.
- Add optional `timeline_order: chronological` (default `newest_first`) and `timeline_tools_per_reasoning: 2` (default `0`, unlimited per block). The latter keeps the latest successful tools per reasoning block while failures/running work remain eligible for the global item/card budgets. Body code reasoning stays chronological; stored history and counts are unchanged.
- Suppress duplicate native retry-exhausted provider warnings only after explicit sidecar acknowledgement. Timeout, rejected/unknown responses and unsupported callbacks preserve native fallback. Raw provider details are not copied into notices; terminal cards retain the failure explanation.
- Recognize exact old hooks reapplied to verified current Git blobs only with explicit `--accept-hermes-upgrade`. Bind resolved HEAD, reject unknown edits or damaged backups, preserve the index and unrelated customizations, and keep install/restore transactional.
- Remove inherited proxy variables only inside preflight test subprocesses, preserving the parent's environment.

The private notice ledger is bounded to 500 scopes, eight members each, seven days. It contains ownership identifiers, application hashes, timestamps and generations, never answers or authorization tokens. Invalid stores are not overwritten; changed applications/policies do not inherit deletion authority. Expiry forgets ownership without deleting platform messages. Platform sends and local registration are not a distributed atomic transaction or permanent exactly-once guarantee. Display checkpoints containing new call IDs require the new reader; older versions may skip them after downgrade.

Automation covers generated callbacks, actual loopback HTTP acknowledgements/rejections, restart/topic isolation, identity mismatch, failed writes, strict source migration/restore, late/duplicate tool events and opt-in display behavior. Full pytest, exact-merge CI, annotated tag, asset checksums and a normal public-tag install remain release gates; evidence is recorded with the [Release](https://github.com/baileyh8/hermes-feishu-streaming-card/releases/tag/v4.6.5).
