## 视觉问题与修复

1. 标题、正文和页脚重复状态与动作。任务标题只保留任务状态，当前动作留在正文；参数只有确认进入实际渲染的过程面板后才从正文移除。过程不可用或容量省略对应工具时保留必要详情。
2. 上游预览已截短，移走参数后看不出脚本目标。任务布局从结构化参数恢复可识别目标，并继续使用已有脱敏与容量限制。
3. 交互转交后旧卡仍写“执行中”，工具又显示“已中断”。旧卡改为静态记录，保留历史，不改变真实执行状态；转交说明只出现一次。
4. 选择卡重复等待页脚、下拉框只有数字、回执沿用运行颜色。去掉冗余等待行，为下拉项增加可识别文字；短按钮显示动作名，完整选项和回调值保留；已记录/失效回执按自身状态配色。
5. `grey` 模板在真实浅色桌面呈现灰底白字，对比度偏弱。依据[官方标题组件](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/content-components/title)改用原生 `default` 中性模板；真实审批转交卡已观察到深色文字和普通背景。
6. 审批暂停后旧卡再次铺开完整范围，造成两处审批展示。最终修复只在实际审批卡保留完整范围和恢复入口，旧卡保持转交说明；不改变 token、回调、权限、过期判定或执行结果。
7. 长过程详情被裁剪时，参数可能既不在面板，也不在正文。仅在当前工具的最新详情完整进入面板后才移走正文参数，增加两种长度限制和复用工具 ID 的正/倒序回归。
8. 第二次审批暂停时，首张 legacy 交互卡可能被错误投影为 JSON 2.0。为旧方言保留原回退路径，并用本地 HTTP 集成交互序列验证没有跨方言 PATCH。
9. 真实 420 秒工具超时后，卡片仍保留陈旧的待选择/再审批提示。终态现在将未决交互收为失效回执，保留完整范围，拒绝旧 token 提交；pending/paused、成功/失败终态、首事件交互/普通开场共八种回归覆盖。最终修复仍待真实客户端复验。
10. 辅助失效回执的慢 PATCH 不得阻塞终态 ACK 或答案，重复终态也不能重复更新回执。该更新复用受管终态任务；首张交互卡就是 owner 时保留原完整终局路径，避免回执覆盖答案。阻塞客户端回归验证了这些条件。
11. clarify 也只在完整回执有确认送达证据时精简历史 owner 重复内容；实际参数完整进入过程面板后，task 工具行改为可读问题摘要。容量不足或未知结构继续保留原内容。
12. task 的 thinking-only 失败依据明确来源将错误放在正文，将结束前思考保留于折叠过程；真实答案和 classic 原行为不改，旧检查点可读，容量判断与正文使用同一展示副本。

短按钮上的动作名称与完整审阅列表承担不同作用。不能因为精简视觉，在容量回退时只留下数字按钮而丢失选项含义；近容量回归继续保留。
